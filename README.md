# KIXBOX Pulse

Личное Android-приложение с аналитикой KIXBOX по базе ClickHouse: продажи интернет-магазина,
розница, товары, клиенты, трафик, реклама, рассылки, доставка, склад и конкуренты.

Инструкция ниже проводит от пустого репозитория до цифр на телефоне. Весь путь занимает
30–40 минут. Шаги 1–2 делаются на GitHub, шаги 3–8 — на сервере Б (85.192.56.142, там же, где
ClickHouse), шаг 9 — на телефоне.

## 1. Как это устроено

```
Телефон ──HTTPS + токен──▶ Cloudflare Tunnel ──▶ API (FastAPI, сервер Б, 127.0.0.1:8095)
                                                      │
                                                      └──▶ ClickHouse (127.0.0.1:8123), пользователь sales_app, только чтение
```

| Папка | Что это |
|---|---|
| `backend/` | Закрытый API. Считает метрики фиксированными SQL-запросами и отдаёт готовые виджеты: KPI, графики, таблицы, теплокарты, воронки, выводы. Произвольный SQL с телефона не принимается. |
| `app/` | Android на Kotlin + Jetpack Compose. Ничего не считает и не знает про таблицы — рисует то, что прислал сервер. Новые метрики добавляются на сервере без пересборки APK. |
| `.github/workflows/build-apk.yml` | Сборка APK и тесты бэкенда в GitHub Actions при каждом пуше в `main`. |
| `backend/deploy/` | SQL для пользователя ClickHouse, скрипт запуска, systemd-юнит, правило для туннеля. |

**Где лежат секреты:** пароль ClickHouse и токен API — только в `backend/.env` на сервере.
Адрес сервера и токен в приложении — только в настройках телефона. В репозитории и в APK их нет.

## 2. Репозиторий и сборка APK на GitHub

### 2.1. Создать репозиторий

1. github.com → **New repository**.
2. Имя: `kixbox-sales-android`, видимость **Public** (у бесплатных Actions для публичных
   репозиториев нет лимита минут).
3. **Не** ставить галочки README, .gitignore, license — репозиторий должен быть пустым.
4. **Create repository**.

Код в репозиторий заливает Claude по готовому адресу. Если заливаете сами:

```bash
cd kixbox-sales-android
git remote add origin https://github.com/civilniy/kixbox-sales-android.git
git push -u origin main
```

### 2.2. Дождаться сборки

1. Вкладка **Actions** → запуск **Build Android APK** стартует сам после пуша.
2. Две задачи:
   - `backend-tests` — прогоняет все разделы на локальном ClickHouse (около 1 минуты);
   - `android` — собирает APK (5–8 минут в первый раз, дальше быстрее из-за кэша).
3. Зелёная галочка → внизу страницы запуска блок **Artifacts** → **KIXBOX-Pulse-APK**.

Если Actions выключены: **Settings → Actions → General → Allow all actions** и
**Actions → Build Android APK → Run workflow**.

### 2.3. Подпись APK

Сборка отладочная, подписывается тестовым ключом, который Actions хранит в кэше
(`kixbox-pulse-debug-keystore-v1`). Пока кэш жив, новые версии ставятся поверх старой.
Если кэш пропадёт (не использовался 7 дней), Android откажется обновлять — удалите
приложение и поставьте заново, настройки подключения придётся ввести повторно.

## 3. Что должно быть на сервере

Сервер Б, Ubuntu, под `root`. Проверка:

```bash
clickhouse-client -q "SELECT version()"       # ClickHouse отвечает локально
docker --version                              # Docker для API (вариант А)
python3 --version                             # 3.11+ — если без Docker (вариант Б)
systemctl status cloudflared --no-pager       # туннель, через который выставлен civi1.ru
git --version
```

Docker, если его нет:

```bash
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker
```

Ресурсы: API занимает около 100 МБ памяти. Нагрузку на ClickHouse ограничивают кэш
(30 минут) и не больше двух одновременных запросов — сервер двухъядерный.

## 5. Пользователь ClickHouse только для чтения

API ходит в базу под отдельным пользователем `sales_app`: только `SELECT`, только с этого
сервера, с лимитами времени и памяти на запрос.

1. Придумайте пароль (или сгенерируйте: `openssl rand -base64 24`).
2. Впишите его в `deploy/create_user.sql` вместо `придумайте-длинный-пароль`:

   ```bash
   nano deploy/create_user.sql
   ```

3. Выполните:

   ```bash
   clickhouse-client --multiquery < deploy/create_user.sql
   ```

4. Проверьте, что пользователь видит данные и не может ничего менять:

   ```bash
   clickhouse-client --user sales_app --password 'ВАШ_ПАРОЛЬ' \
     -q "SELECT count() FROM kixbox.c1_items"
   clickhouse-client --user sales_app --password 'ВАШ_ПАРОЛЬ' \
     -q "CREATE TABLE kixbox.t (x UInt8) ENGINE = Memory"   # должно упасть с ошибкой прав
   ```

Права выдаются на базы `kixbox`, `brandshop`, `nuwstore`, `studioslow`, `leform`. Если
появится новая база конкурента — добавьте `GRANT SELECT ON <база>.* TO sales_app;`.

> Если `CREATE USER` отвечает, что управление доступом выключено: в
> `/etc/clickhouse-server/users.xml` у пользователя `default` должно быть
> `<access_management>1</access_management>`, затем `systemctl restart clickhouse-server`.

## 6. Файл настроек .env

```bash
cp .env.example .env
openssl rand -hex 32        # это будет токен для телефона — скопируйте
nano .env
chmod 600 .env
```

| Переменная | Что вписать | По умолчанию |
|---|---|---|
| `CLICKHOUSE_URL` | адрес HTTP-интерфейса ClickHouse с точки зрения API | `http://127.0.0.1:8123` |
| `CLICKHOUSE_USER` | пользователь из шага 5 | `sales_app` |
| `CLICKHOUSE_PASSWORD` | пароль из шага 5 | — |
| `SALES_API_TOKEN` | результат `openssl rand -hex 32` | — (без него API не отвечает) |
| `CACHE_MINUTES` | сколько минут держать готовый раздел | `30` |
| `MAX_PARALLEL_QUERIES` | запросов в ClickHouse одновременно | `2` |
| `QUERY_TIMEOUT_S` | таймаут HTTP-запроса к ClickHouse | `90` |
| `WARMUP` | `1` — прогревать «Месяц» и «7 дней» в фоне | `1` |
| `DIRECT_LOGIN` | логин Директа для раздела «Реклама» | `Kixbox-cnx` |
| `METRIKA_SITE` | сайт в `ya_metrika` | `kixbox.ru` |

## 7. Запуск API

### Вариант А — Docker (рекомендую)

```bash
./deploy/run.sh
```

Скрипт собирает образ `kixbox-pulse-api`, перезапускает контейнер с
`--restart unless-stopped` и сетью хоста и проверяет `/api/v1/health`. Ожидаемый ответ:

```json
{"ok":true,"version":1}
```

API слушает только `127.0.0.1:8095` — снаружи порт недоступен.

Журнал и управление:

```bash
docker logs -f --tail 100 kixbox-pulse-api     # журнал: время сборки каждого раздела, медленные запросы
docker restart kixbox-pulse-api
docker rm -f kixbox-pulse-api                  # остановить
```

### Вариант Б — без Docker, через systemd

```bash
python3 -m venv /opt/kixbox-pulse/venv
/opt/kixbox-pulse/venv/bin/pip install -r requirements.txt
cp deploy/kixbox-pulse.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now kixbox-pulse
systemctl status kixbox-pulse --no-pager
journalctl -u kixbox-pulse -f                   # журнал
```

### Проверка с токеном

```bash
TOKEN=$(grep SALES_API_TOKEN .env | cut -d= -f2)
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8095/api/v1/meta | head -c 600; echo
curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:8095/api/v1/section/overview?period=mtd" | head -c 600; echo
```

В `meta` блок `freshness` показывает последнюю дату по каждому источнику и `end` — день, по
который строится отчёт. Первый расчёт раздела занимает 5–40 секунд, повторный — мгновенно.

## 8. Публичный адрес через Cloudflare Tunnel

Телефону нужен HTTPS-адрес. Используем уже работающий туннель — новых портов открывать не надо.

1. Узнайте имя туннеля:

   ```bash
   cloudflared tunnel list
   cat /etc/cloudflared/config.yml
   ```

2. Добавьте в `/etc/cloudflared/config.yml` в список `ingress` правило из
   `deploy/cloudflared-ingress.yml` — **перед** последним правилом `service: http_status:404`:

   ```yaml
   ingress:
     # ... существующие правила ...
     - hostname: pulse.civi1.ru
       service: http://127.0.0.1:8095
     - service: http_status:404
   ```

3. Проверьте конфиг, заведите DNS-запись и перезапустите:

   ```bash
   cloudflared tunnel ingress validate
   cloudflared tunnel ingress rule https://pulse.civi1.ru     # должно показать правило на 8095
   cloudflared tunnel route dns <ИМЯ_ТУННЕЛЯ> pulse.civi1.ru
   systemctl restart cloudflared
   ```

4. Проверьте снаружи (с любого компьютера или телефона):

   ```bash
   curl https://pulse.civi1.ru/api/v1/health
   ```

Имя `pulse.civi1.ru` можно поменять — тогда и в приложении вводится другой адрес.

> Если `cloudflared` стоит не на сервере Б, а на сервере А: в правиле туннеля укажите
> `service: http://85.192.56.142:8095`, в `Dockerfile` замените `--host 127.0.0.1` на
> `--host 0.0.0.0` и откройте порт 8095 файрволом **только** для 79.137.195.114.

## 9. Установка и подключение приложения

1. Скачайте артефакт **KIXBOX-Pulse-APK** (шаг 2.2), распакуйте ZIP.
2. Откройте `KIXBOX-Pulse.apk` на телефоне. Android попросит разрешить установку из этого
   источника (браузер или файловый менеджер) — разрешите.
3. При первом запуске откроется экран подключения:
   - **Адрес** — `https://pulse.civi1.ru` (без `/api` в конце);
   - **Токен** — значение `SALES_API_TOKEN` из `.env`.
4. **Подключиться**: приложение проверит адрес и токен и откроет «Сводку».

Пользоваться:

| Действие | Как |
|---|---|
| Сменить раздел | тап по вкладке сверху или свайп влево-вправо |
| Сменить период | чипы «День … Год» под вкладками |
| Значения на графике | тап по столбцу или точке, повторный тап — снять |
| Сортировка таблицы | тап по заголовку колонки, повторный — обратный порядок |
| Вся таблица | «Показать все · N» под таблицей; широкие таблицы листаются вбок |
| Пояснение к показателю | тап по карточке со значком ⓘ |
| Пересчитать раздел без кэша | потянуть экран вниз |
| Обновить всё | кнопка ⟳ в шапке |
| Свежесть источников | тап по строке с датой под заголовком (зелёная точка — всё свежее) |
| Сменить сервер или токен | шестерёнка |

Без сети приложение показывает последние сохранённые данные с пометкой.

## 10. Обновления

**Приложение:** после каждого пуша в `main` Actions собирает новый APK — скачать и поставить
поверх (шаг 9, настройки сохраняются).

**Сервер** (новые метрики, исправления запросов):

```bash
cd /opt/kixbox-pulse && git pull
cd backend && ./deploy/run.sh                      # вариант А
# или: systemctl restart kixbox-pulse              # вариант Б
```

Большинство изменений — только серверные: новые KPI, таблицы и графики появляются в
приложении без переустановки.

**Смена токена:** новый `SALES_API_TOKEN` в `.env` → перезапуск API → в приложении шестерёнка →
новый токен.

## 11. Разделы и методики

| Раздел | Источник | Что внутри |
|---|---|---|
| Сводка | всё | план месяца: факт, прогноз, нужно в день, темп 7 дней, прошлый год; автоматические выводы; KPI ИМ, трафика, рекламы и сети; выручка по дням против прошлого года; каналы сети |
| Продажи ИМ | `c1_items` | спрос, заказы, отгрузки, возвраты, чистая выручка, чек, цена товара, UPT, скидка, доставка; теплокарта заказов день × час; средний спрос по дням недели; доставка × оплата; способы получения и отмены; статусы; города; глубина скидки; ценовые сегменты; сезоны; пол |
| Товары | `c1_items` | бренды с долей, динамикой, скидкой и возвратами; кто двигает выручку; категории; типы; топ товаров по выручке и штукам; лидеры возвратов; размеры одежды и обуви; новые артикулы |
| Магазины | Mindbox | выручка сети, розница, онлайн, доля розницы, чеки, чек, UPT, доля чеков с картой; таблица точек к прошлому периоду и году; выручка по каналам; чеки по часам; выручка магазинов по дням недели; размер чека |
| Клиенты | Mindbox | покупатели, новые, повторные, выручка на клиента; каналы покупателей (только онлайн, только магазины, оба); частота за 12 месяцев; давность последней покупки; когорты возвращаемости; баллы; программа лояльности; пол и возраст |
| Трафик | `ym_visits` + 1С | визиты, посетители, новые, отказы, время, глубина, мобильные, корзина, конверсия; воронка целей до заказа 1С; источники, устройства, новые/вернувшиеся, типы страниц входа, страницы входа, города, UTM — с фактическими заказами 1С |
| Реклама | `ya_direct` + визиты + 1С | расход, ДРР, показы, клики, CTR, CPC, конверсии, заказы из рекламы, CPO, ROAS; типы кампаний; все кампании с ДРР и CPO по заказам 1С |
| Рассылки | Mindbox | отправлено, получатели, открытия, CTR, CTOR, отписки, недоставка, визиты и заказы из писем; каналы; триггерные против массовых; все рассылки |
| Доставка | Dalli + Алгоритм | отправления, полный выкуп, отказы, выкуп при оплате на месте, сроки (среднее и 90%), тарифы, экономика доставки; службы; выкуп по неделям; города |
| Склад | InSales + 1С | остатки в штуках и деньгах, запас в днях, оборот, полнота размерных сеток, неликвид 90 дней; бренды и категории на складе; новые карточки |
| Конкуренты | `brandshop`, `nuwstore`, `studioslow`, `leform` | оценка продаж и штук, скидки, движение стока, бренды конкурентов против Kixbox, топ моделей |

**Периоды:** день, 7 дней, 30 дней, месяц с начала, прошлый месяц, квартал, 90 дней, год.
Сравнение — с предыдущим периодом (для месяца — те же дни прошлого месяца, для дня — тот же
день неделю назад) и с прошлым годом. До 45 дней графики по дням, до 200 — по неделям, дальше —
по месяцам.

**Последний день отчёта** — последний завершённый день 1С: день считается завершённым, если в нём
есть отгрузка после 19:00 (правило `plan_fact`). Для остальных источников берётся тот же день.

**Методики:**

- Чистая выручка ИМ = отгрузки товара и доставки минус возвраты, склады 400 и 401, сайт не Hike,
  по датам своих документов. Совпадает с `plan_fact` до рубля.
- Сумма заказов — спрос по дате оформления (`Заказ`, «Спейс Джем», «Копия kixbox»). Не выручка.
- Скидка — от базовой цены: `1 − сумма / (цена × количество)`.
- Розница и сеть — Mindbox: позиции без корзины, отмен и возвратов, даты переведены из UTC в МСК.
- Новый покупатель — первый заказ в истории Mindbox попал в период.
- Атрибуция — `purchase_id` визита Метрики → `KB` + номер в 1С. Метрика видит около двух третей
  заказов, поэтому ДРР и CPO кампаний — оценка сверху.
- Расход рекламы — `ya_direct` с `FINAL`, логин Kixbox-cnx.
- Выкуп при оплате на месте — чек при вручении к стоимости вложения, завершённые отправления.
- Конкуренты — продажа = уменьшение остатка размера между срезами, по цене на начало окна;
  продажи дня D лежат в окне D + 1.

## 12. Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| Приложение: «Неверный токен доступа» | Токен в приложении не совпадает с `SALES_API_TOKEN`. Скопируйте заново, без пробелов. |
| «Адрес не найден» / «Нет связи с сервером» | Нет DNS-записи или туннель не перезапущен: `curl https://pulse.civi1.ru/api/v1/health`, шаг 8. |
| «Сервер недоступен (HTTP 502)» | Туннель жив, API нет: `docker ps`, `docker logs kixbox-pulse-api`. |
| «Сервер недоступен (HTTP 503)» | Не задан `SALES_API_TOKEN` в `.env` — заполнить и перезапустить. |
| Раздел: «Раздел не собрался» | Упал SQL-запрос. `docker logs kixbox-pulse-api \| grep -A5 failed` — в журнале текст ошибки и запрос. |
| В журнале `Authentication failed` | Неверный `CLICKHOUSE_PASSWORD` или пользователь не создан (шаг 5). |
| В журнале `Not enough privileges` | Нет `GRANT SELECT` на базу — добавить (шаг 5). |
| В журнале `TIMEOUT_EXCEEDED` / `MEMORY_LIMIT` | Тяжёлый период (год) при занятом сервере. Повторить позже или поднять `max_execution_time` в `create_user.sql` и выполнить `ALTER USER`. |
| Цифры «вчерашние» | Отчёт идёт по последний завершённый день 1С. Тап по дате в шапке — видно, какой источник отстаёт. Загрузите 1С. |
| Нули в «Клиентах» или «Рассылках» | Не догрузился Mindbox: `freshness` → `mindbox` / `mailings`. |
| Пусто в «Конкурентах» за прошлые периоды | Срезы начинаются с 1 сентября (Brandshop), 21 сентября (NUW), 22–23 сентября (Studio Slow, Leform). |
| APK не ставится поверх старого | Пропал кэш тестовой подписи (шаг 2.3) — удалить приложение и поставить заново. |
| Долго открывается раздел | Первый расчёт периода. Далее 30 минут из кэша; «Месяц» и «7 дней» прогреваются сами. |

Посмотреть, что отдаёт сервер, можно прямо из браузера с расширением для заголовков или так:

```bash
curl -s -H "Authorization: Bearer $TOKEN" "https://pulse.civi1.ru/api/v1/section/sales?period=7d&refresh=true" | python3 -m json.tool | less
```

## 13. Безопасность

- API принимает только запросы с токеном; сравнение токена — в постоянное время.
- Запросы к ClickHouse собраны на сервере из фиксированных шаблонов. От телефона приходят только
  идентификатор раздела и период из списка — оба проверяются.
- Пользователь `sales_app` — `readonly = 1`, только `SELECT`, вход только с локального хоста.
- API слушает `127.0.0.1`, наружу выходит только через туннель Cloudflare с HTTPS.
- Персональные данные клиентов (имена, телефоны, почты) API не отдаёт — только агрегаты.
- Дополнительно можно закрыть `pulse.civi1.ru` через Cloudflare Access (Zero Trust → Access →
  Applications) с политикой Service Token — тогда без него не пройдёт даже `health`.
- Репозиторий публичный: в нём логика запросов (склады, юрлица, ID точек Mindbox), но нет
  паролей, токенов и данных.

## 14. Разработка и тесты

```bash
cd backend
pip install -r requirements-dev.txt
python -m unittest discover -s tests -t . -v
```

Тесты поднимают локальный ClickHouse (chdb, версия 26.x — как на сервере) со схемой боевых
таблиц и синтетическими данными и прогоняют **каждый раздел для каждого периода**, проверяя
SQL, типы и форму всех виджетов. Те же тесты идут в Actions перед сборкой APK.

**Добавить метрику:** раздел — это файл `backend/sections/<раздел>.py` с функцией `build(ctx)`,
которая возвращает список виджетов из `backend/widgets.py` (`kpi`, `chart`, `table`, `share`,
`heatmap`, `funnel`, `insights`, `note`). Окна периода — `ctx.wexpr(...)` и `ctx.wfilter(...)`,
общие запросы — в `sections/common.py`. Новый раздел регистрируется в `sections/__init__.py`
и сразу появляется вкладкой в приложении.

**Формат ответа API:**

| Эндпоинт | Что отдаёт |
|---|---|
| `GET /api/v1/health` | `{"ok": true}` без токена — для проверки доступности |
| `GET /api/v1/meta` | список разделов, периодов и свежесть источников |
| `GET /api/v1/section/{id}?period=mtd&refresh=false` | виджеты раздела за период; `refresh=true` — пересчитать без кэша |

Приложение: `app/src/main/java/ru/kixbox/pulse/` — `data/` (модели и сеть), `ui/` (тема,
форматирование, графики, виджеты), `MainActivity.kt` (экраны), `PulseViewModel.kt` (состояние
и кэш).
